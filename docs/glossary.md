## Official Terminology Reference

This glossary defines the official terminology used throughout the FireGuard project documentation, codebase, graduation book, and all related materials. Consistent use of these terms is mandatory across all project artifacts.

---

| # | Term | Definition |
|---|------|-----------|
| 1 | **FireEvent** | The core data entity representing a single fire or smoke detection incident. A `FireEvent` is created in the Django backend when the AI service detects fire or smoke and successfully reports it via `POST /api/events/`. Each `FireEvent` has a status (`active`, `resolved`, or `false_alarm`), an event type (`fire` or `smoke`), an AI confidence score, an optional snapshot image, and timestamps for detection and resolution. Stored in the `events_fireevent` SQLite3 table. |
| 2 | **AI Camera Node** | The physical setup comprising a camera device (USB or WiFi camera connected to a computer) running the `camera.py` script with the YOLOv8 model. In the FireGuard architecture, the AI Camera Node acts as an edge device that performs local inference and reports results to the centralized backend. In the current implementation, a single AI Camera Node is supported (`CAMERA_ID = 1`, `cv2.VideoCapture(0)`). |
| 3 | **Detection Event** | The real-time occurrence of the YOLOv8 model identifying fire or smoke in a camera frame with a confidence score at or above the configured threshold (50%). A Detection Event may or may not result in a `FireEvent` creation, depending on the cooldown mechanism. If the cooldown has not expired, the Detection Event is suppressed. |
| 4 | **Confidence Threshold** | The minimum confidence score required for the YOLOv8 model to report a detection. Set to `0.5` (50%) in `camera.py` via `model(frame, conf=0.5)`. Detections below this threshold are discarded by the model's internal non-maximum suppression. The confidence value is converted from the model's 0.0–1.0 scale to a 0–100 percentage scale before being sent to the backend as `ai_confidence`. |
| 5 | **Active Event** | A `FireEvent` with `status = 'active'`. This is the default status when an event is created. An active event indicates that a fire or smoke detection has occurred and has not yet been reviewed or resolved by a user. The Flutter app can query the most recent active event via `GET /api/events/active/`. |
| 6 | **Notification Payload** | The structured data package sent via Firebase Cloud Messaging (FCM) when a `FireEvent` is created or resolved. The payload includes both a `notification` object (title and body for system tray display) and a `data` object (structured fields for client-side processing). Key data fields include: `type`, `event_id`, `camera_id`, `camera_name`, `location`, `zone`, `event_type`, `ai_confidence`, and `detected_at`. In the Flutter app, this is parsed into the `AlertPayload` Dart class. |
| 7 | **Edge Node** | Synonymous with **AI Camera Node**. Refers to the local machine running `camera.py` that performs AI inference at the "edge" of the network (close to the camera source) rather than in the cloud or on the backend server. The edge node captures frames, runs YOLOv8, and sends only the detection results and snapshots to the centralized backend. |
| 8 | **Event Resolution** | The process of a user marking an active `FireEvent` as either `resolved` or `false_alarm` via the Flutter app or API. Resolution is performed by calling `PATCH /api/events/{id}/resolve/` or `PATCH /api/events/{id}/false-alarm/`. When resolved, the event's `resolved_at` timestamp is set to the current time, and a `send_resolved_alert()` notification is dispatched to users with `resolved_alerts` enabled. |
| 9 | **Snapshot** | An annotated JPEG image captured at the moment of a detection event. The snapshot is generated by `camera.py` using `cv2.imwrite()` on the annotated frame produced by `r.plot()` (which includes YOLOv8 bounding boxes, class labels, and confidence scores). The snapshot is uploaded to the backend as a multipart file in the `snapshot` field and stored in the `media/snapshots/` directory. Snapshots provide visual evidence for fire event verification. |
| 10 | **FCM** | **Firebase Cloud Messaging** — Google's cross-platform push notification service used by FireGuard to deliver real-time alerts from the Django backend to the Flutter mobile application. The backend uses the Firebase Admin SDK (`firebase_admin` Python package) to send multicast messages to registered device tokens. The Flutter app uses `firebase_messaging` and `flutter_local_notifications` packages to receive and display these notifications. FCM supports both Android and iOS platforms. |
| 11 | **YOLOv8** | **You Only Look Once, version 8** — A state-of-the-art real-time object detection model from Ultralytics. FireGuard uses a custom-trained YOLOv8 model (`best.pt`) that has been trained to detect two classes: `fire` and `smoke`. The model is loaded via the `ultralytics` Python package and runs inference on each camera frame with a confidence threshold of 0.5. YOLOv8 performs detection in a single forward pass through the neural network, making it suitable for real-time applications. |
| 12 | **Inference Pipeline** | The complete processing chain from raw camera frame to detection result. In FireGuard, the inference pipeline consists of: (1) frame capture via OpenCV, (2) preprocessing by the Ultralytics library (resize, normalize, letterbox), (3) PyTorch forward pass through the YOLOv8 model, (4) non-maximum suppression to filter low-confidence detections, and (5) result extraction (bounding boxes, class IDs, confidence scores). The pipeline runs continuously in the `while True` loop of `camera.py`. |

## Additional Terms

| Term | Definition |
|------|-----------|
| **Cooldown** | A 10-second suppression interval between consecutive alerts in `camera.py`. After a detection event successfully creates a `FireEvent` (HTTP 201 response), the system waits at least 10 seconds before sending the next alert to prevent flooding the backend with duplicate events for the same ongoing fire. Controlled by `COOLDOWN_SECONDS = 10` and `last_sent_time`. |
| **DRF** | **Django REST Framework** — The Python library used to build the RESTful API layer of the FireGuard backend. Provides serializers, views, authentication, permissions, and pagination. |
| **Token Authentication** | The authentication method used by the FireGuard API. After login or registration, the server returns an authentication token. The Flutter app includes this token in the `Authorization: Token <key>` header of all subsequent API requests. Implemented via DRF's `rest_framework.authtoken`. |
| **Zone** | A logical grouping of cameras in the backend database. Zones represent physical areas (e.g., "Storage Area", "Main Hall", "Parking Lot") and are used to organize cameras and filter events. Each camera belongs to exactly one zone. |
| **Provider** | The state management solution used in the Flutter app. The `provider` package provides reactive, dependency-injectable state objects (`ChangeNotifier`) that UI widgets can listen to for updates. Providers are registered at the root of the widget tree via `MultiProvider`. |
| **GoRouter** | The declarative routing library used in the Flutter app for navigation. Defines all app routes as a configuration object and supports deep linking, path parameters, and programmatic navigation. Used for notification-triggered navigation to the alert screen. |
| **PythonAnywhere** | The cloud hosting platform where the Django backend is deployed. Provides a free tier with WSGI application support, file-based storage, and a SQLite3-compatible environment. The production URL is `bodareda0001.pythonanywhere.com`. |
| **MulticastMessage** | A Firebase Admin SDK message type that sends the same notification to multiple device tokens in a single API call. Used by `send_fire_alert_to_all()` and `send_resolved_alert()` in `notifications/fcm.py` to efficiently notify all opted-in users. |
| **AlertPayload** | A Dart class in the Flutter app (`core/models/notification_payload.dart`) that maps the FCM `data` payload to a structured object. Contains fields for `type`, `eventId`, `cameraId`, `cameraName`, `location`, `zone`, `eventType`, `aiConfidence`, and `detectedAt`. Used by the `AlertScreen` to display event details. |
| **DatabaseService** | A singleton service in the Flutter app (`core/services/database_service.dart`) that manages a local SQLite database (`fire_guard.db`) for caching notification history on the device. Enables offline access to past notifications. |
